# IO任务日志收集和数据可视化实现计划

## 一、需求分析

1. **多节点多分区IO任务**：支持对多个节点上的多个分区执行IO测试
2. **日志收集**：收集fio结果日志、iostat日志和平台执行指令日志，统一放在任务凭证指定目录下
3. **日志压缩下载**：任务完成后将所有日志压缩成一个压缩包下载到本地
4. **IO任务状态展示**：清晰显示哪些IO模型任务已完成，实时展示详细数据和性能抖动图
5. **详细数据分节点分分区展示**：支持按节点和分区查看详细数据

## 二、实现计划

### 1. 日志收集优化

#### 1.1 系统执行指令日志收集
- **后端修改**：
  - 在 `log_collector.py` 中添加 `collect_system_log` 方法，用于收集平台执行指令的日志
  - 在任务执行过程中，记录所有执行的指令到系统日志文件
  - 确保系统日志也存储在任务凭证指定的目录下

#### 1.2 统一目录管理
- **后端修改**：
  - 确保所有日志（fio、iostat、system）都存储在任务凭证指定的目录结构中
  - 优化 `log_collector.py` 中的目录创建逻辑，使用统一的路径格式

### 2. 日志压缩下载功能

#### 2.1 完善打包逻辑
- **后端修改**：
  - 完善 `package_task_logs` 方法，确保包含所有类型的日志
  - 确保打包文件存储在可访问的位置，便于前端下载

#### 2.2 前端下载界面
- **前端修改**：
  - 在 `TaskDetail.vue` 中添加日志下载按钮
  - 实现调用后端API下载压缩包的功能

### 3. IO任务状态展示优化

#### 3.1 实时IO模型任务状态
- **前端修改**：
  - 优化 `TaskDetail.vue` 中的IO任务列表，更清晰地显示每个IO模型任务的完成状态
  - 为每个IO模型任务添加进度条和状态标签

#### 3.2 实时数据展示
- **前端修改**：
  - 实现实时加载和展示测试结果数据
  - 添加刷新按钮，允许用户手动刷新最新数据

### 4. 性能抖动图实现

#### 4.1 实时性能抖动图
- **前端修改**：
  - 优化 `IOJitterChart.vue` 组件，支持实时展示性能抖动
  - 实现WebSocket连接，实时接收性能数据
  - 支持选择不同的性能指标（IOPS、带宽、延迟）和时间范围

#### 4.2 多节点多分区支持
- **前端修改**：
  - 实现按节点和分区筛选性能抖动数据
  - 支持在同一图表中对比不同节点或分区的性能

### 5. 详细数据分节点分分区展示

#### 5.1 节点和分区筛选
- **前端修改**：
  - 在 `TaskDetail.vue` 或 `Results.vue` 中添加节点和分区筛选功能
  - 实现按节点和分区分组展示测试结果

#### 5.2 详细数据表格
- **前端修改**：
  - 优化测试结果表格，支持按节点和分区排序
  - 添加导出功能，允许用户导出详细数据

## 四、预期效果

1. **多节点多分区支持**：系统能够同时对多个节点上的多个分区执行IO测试
2. **完整日志收集**：自动收集fio结果日志、iostat日志和平台执行指令日志
3. **便捷日志下载**：任务完成后可一键下载所有日志的压缩包
4. **实时状态展示**：清晰显示每个IO模型任务的完成状态，支持实时查看详细数据
5. **直观性能抖动图**：实时展示性能抖动情况，支持按节点和分区筛选

## 六、风险评估

1. **性能风险**：多节点同时执行IO测试可能导致系统负载过高，需要监控系统资源使用情况
2. **网络风险**：大量日志数据传输可能占用较多网络带宽，需要优化日志传输机制
3. **存储风险**：长期存储大量日志可能导致存储空间不足，需要考虑日志轮换和清理策略
4. **兼容性风险**：不同节点的操作系统和硬件配置可能存在差异，需要确保测试工具的兼容性

通过以上实现计划，我们可以全面满足用户的需求，提供一个功能完善、界面友好的IO任务管理和数据可视化系统。
