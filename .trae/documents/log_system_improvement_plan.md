## 问题分析结果
1. **日志格式问题**：
   - 后端日志使用标准Python logging格式，但通过WebSocket发送的实时日志是直接文本内容
   - 前端收到的日志只是简单文本行，没有结构化信息
   - 不同类型的日志（系统消息、fio输出、iostat输出）混合在一起

2. **日志内容问题**：
   - 原始fio和iostat输出格式复杂，难以阅读
   - 没有对日志进行分类或过滤
   - 缺乏上下文信息和日志级别区分

3. **前端展示问题**：
   - 前端只是简单按时间顺序显示所有日志
   - 没有日志级别过滤和搜索功能
   - 没有日志可视化和分析能力

4. **日志管理问题**：
   - 日志存储在本地文件系统，没有集中管理
   - 缺乏日志轮转和保留策略
   - 没有告警机制

## 详细设计方案

### 1. 日志级别分类和使用规范
| 级别 | 数值 | 描述 | 使用场景 |
|------|------|------|----------|
| DEBUG | 10 | 详细的调试信息 | 开发和调试时使用，记录详细的执行过程 |
| INFO | 20 | 正常的运行信息 | 记录任务开始、完成、进度等正常运行状态 |
| WARNING | 30 | 警告信息 | 资源不足、配置问题、性能异常等需要关注的情况 |
| ERROR | 40 | 错误信息 | 执行失败、异常等需要处理的错误 |
| CRITICAL | 50 | 严重错误 | 系统崩溃、数据丢失等严重问题 |

### 2. 结构化日志格式

#### 2.1 后端日志格式（JSON）
```json
{
  "timestamp": "2023-10-01T12:00:00.000Z",
  "level": "INFO",
  "module": "tasks",
  "message": "任务开始执行",
  "context": {
    "task_id": 123,
    "node_id": 456,
    "io_test_case_id": 789,
    "operation": "execute_task"
  }
}
```

#### 2.2 WebSocket日志传输格式
```json
{
  "type": "task_log",
  "data": {
    "timestamp": "2023-10-01T12:00:00.000Z",
    "level": "INFO",
    "module": "tasks",
    "message": "任务开始执行",
    "context": {
      "task_id": 123,
      "node_id": 456,
      "io_test_case_id": 789,
      "operation": "execute_task"
    }
  }
}
```

### 3. 日志存储和查询方案

#### 3.1 日志存储
- **存储位置**：`backend/logs/`目录
- **文件命名**：`app-YYYY-MM-DD.log`
- **轮转策略**：每日轮转
- **保留期限**：7天
- **文件格式**：JSON格式，每行一条日志

#### 3.2 日志查询
- **API接口**：`/logs/query`
- **查询参数**：
  - `start_time`：开始时间
  - `end_time`：结束时间
  - `level`：日志级别
  - `module`：模块名称
  - `keyword`：关键词
  - `task_id`：任务ID

### 4. 前端日志观察界面设计

#### 4.1 主要功能
- **实时日志展示**：按时间顺序显示实时日志
- **日志级别过滤**：按DEBUG、INFO、WARNING、ERROR、CRITICAL过滤
- **日志分类**：按模块、操作类型等分类
- **日志搜索**：支持关键词搜索
- **日志可视化**：展示日志级别分布、模块分布等统计图表
- **日志告警**：实时显示告警信息

#### 4.2 界面布局
- **顶部**：过滤条件和搜索框
- **中部**：日志列表，支持分页
- **右侧**：统计图表和告警信息
- **底部**：日志详情展示

#### 4.3 日志展示样式
- **DEBUG**：灰色
- **INFO**：蓝色
- **WARNING**：黄色
- **ERROR**：红色
- **CRITICAL**：深红色

### 5. 日志告警机制

#### 5.1 告警规则
- **基于级别**：ERROR和CRITICAL级别自动告警
- **基于关键词**：包含特定关键词（如"失败"、"错误"、"异常"）的日志告警
- **基于阈值**：特定操作的失败次数超过阈值告警

#### 5.2 告警通知方式
- **前端通知**：在前端界面显示告警信息
- **邮件通知**：发送邮件给相关人员（可选）
