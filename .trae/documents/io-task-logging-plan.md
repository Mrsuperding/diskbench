# IO 任务日志记录与测试实现计划

## 需求分析

### 1. 用户友好的日志记录系统
- **目标**: 在 IO 任务执行过程中，生成用户可理解的日志
- **场景**:
  - 上传文件到节点时：显示"当前上传工具到 XX 节点"
  - 执行 IO 模型时：显示具体执行的 fio 命令
  - 收集日志时：显示"收集中"
  - 任务完成时：显示"任务已经完成"

### 2. 数据收集与 IO 模型匹配问题
- **问题**: 任务执行完成后数据收集不到
- **可能原因**: 匹配规则有问题
- **IO 模型名称**: 需要与编辑 IO 用例模型界面规则一致

### 3. 测试策略
- 先做后端接口测试
- 再做前端测试
- 生成测试用例到测试文件夹
- 代码简洁，单个函数代码量不超标

## 实现步骤

### 第一阶段：代码调研与分析
1. **分析现有任务执行流程**
   - 查看 TestTask 和 TaskExecution 模型
   - 分析任务执行的后台逻辑
   - 找到文件上传、fio 命令执行、日志收集的关键代码位置

2. **分析 IO 模型匹配规则**
   - 查看 IO 模型的定义和解析逻辑
   - 分析数据收集的匹配规则
   - 对比前端编辑 IO 用例模型界面的规则

3. **分析现有日志系统**
   - 查看是否已有日志记录机制
   - 确定日志存储方式（数据库/文件）
   - 分析日志与任务的关联关系

### 第二阶段：用户友好日志系统实现
4. **设计日志数据结构**
   - 创建或复用日志表（可能需要 TestLog 或新建表）
   - 定义日志级别（info, warning, error）
   - 设计日志格式（时间戳、任务 ID、节点信息、消息内容）

5. **在关键节点添加日志记录**
   - **文件上传阶段**: 在上传工具到节点时添加日志
   - **IO 模型执行阶段**: 在执行 fio 命令时记录具体命令
   - **日志收集阶段**: 在收集日志时添加进度提示
   - **任务完成阶段**: 在任务完成时添加完成状态日志

6. **日志查询接口**
   - 确保前端可以查询到任务的详细日志
   - 可能需要添加或修改现有的日志查询 API

### 第三阶段：数据收集与 IO 模型匹配修复
7. **调试数据收集问题**
   - 添加调试日志追踪数据收集流程
   - 检查 IOStatMetric 和 IOPerformanceData 的插入逻辑
   - 分析为什么数据收集不到

8. **修复 IO 模型匹配规则**
   - 对比前端 IO 模型名称规则
   - 修改后端匹配逻辑使其一致
   - 确保 IO 模型名称解析正确

### 第四阶段：后端接口测试
9. **创建后端测试用例**
   - 测试任务创建接口
   - 测试任务执行接口
   - 测试日志查询接口
   - 测试数据收集接口
   - 测试 IO 模型匹配逻辑

10. **执行后端测试**
    - 运行测试用例
    - 记录测试结果
    - 修复发现的问题

### 第五阶段：前端测试
11. **创建前端测试用例**
    - 测试 IO 任务列表展示
    - 测试 IO 任务详情页面
    - 测试日志详情展示
    - 测试数据展示

12. **执行前端测试**
    - 运行前端测试
    - 验证用户日志显示
    - 验证数据完整性

## 技术要点

### 日志记录方案
- 使用现有的 TestLog 模型或创建新的 UserFriendlyLog 模型
- 在任务执行的各个阶段插入日志记录
- 确保日志与任务 ID、节点 ID 关联

### 数据收集匹配规则
- 分析 fio 输出格式
- 确保正则表达式或解析逻辑正确
- 统一 IO 模型命名规范

### 测试代码规范
- 每个测试函数不超过 50 行代码
- 使用 pytest 或 unittest 框架
- 测试数据独立，可重复运行

## 风险与挑战
1. 任务执行逻辑可能分散在多个文件中
2. 数据收集匹配规则可能复杂
3. 需要确保日志记录不影响任务执行性能

## 验收标准
1. 用户可以在任务详情中看到清晰的执行日志
2. 日志包含上传、执行、收集、完成等关键节点
3. 任务完成后数据能正确收集
4. IO 模型名称显示与编辑界面一致
5. 后端测试通过
6. 前端测试通过
