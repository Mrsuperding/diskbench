# IO性能测试平台数据库设计方案

## 1. 设计原则

### 1.1 核心原则
- **数据完整性**: 通过主键、外键、唯一约束确保数据一致性
- **性能优化**: 合理设计索引，优化查询性能
- **扩展性**: 预留扩展字段，支持未来功能增强
- **安全性**: 敏感信息加密存储，权限分级控制
- **可维护性**: 清晰的表结构和字段命名规范

### 1.2 命名规范
- 表名使用小写下划线命名法：`user_profiles`, `test_results`
- 字段名使用小写下划线命名法：`user_id`, `created_at`
- 索引名以`idx_`前缀：`idx_username`, `idx_task_status`
- 外键名以`fk_`前缀：`fk_user_role`

## 2. 数据库架构

### 2.1 数据库分层
```
Application Layer (Flask)
    ↓
Data Access Layer (SQLAlchemy ORM)
    ↓
Database Layer (MySQL 8.0)
    ↓
Storage Layer (InnoDB Engine)
```

### 2.2 数据流架构
```
Frontend Request → API Layer → Business Logic → Data Validation → Database Operations → Response
```

## 4. 索引优化策略

### 4.1 索引设计原则
- **主键索引**: 所有表的主键自动创建聚簇索引
- **唯一索引**: 用于保证数据唯一性的字段
- **普通索引**: 用于加速查询的字段
- **组合索引**: 多条件查询的字段组合
- **前缀索引**: 长文本字段的前缀索引

### 4.2 关键索引配置
```sql
-- 用户查询优化
CREATE INDEX idx_user_login ON users(username, status);
CREATE INDEX idx_user_created ON users(created_at, role);

-- 任务查询优化
CREATE INDEX idx_task_status_time ON test_tasks(status, created_at);
CREATE INDEX idx_task_user_status ON test_tasks(created_by, status);

-- 结果查询优化
CREATE INDEX idx_result_task_time ON test_results(task_id, timestamp);
CREATE INDEX idx_result_node_time ON test_results(node_id, timestamp);

-- 监控数据查询优化
CREATE INDEX idx_metrics_time_type ON system_metrics(timestamp, metric_type);
```

ALTER TABLE test_results

## 6. 视图设计

### 6.1 任务概览视图
```sql
CREATE VIEW task_overview AS
SELECT 
    t.id,
    t.name,
    t.status,
    t.progress,
    t.created_at,
    t.started_at,
    t.completed_at,
    u.username AS created_by,
    tc.name AS test_case_name,
    tc.tool_type,
    COUNT(tr.id) AS result_count,
    MAX(tr.timestamp) AS last_result_time
FROM test_tasks t
LEFT JOIN users u ON t.created_by = u.id
LEFT JOIN io_test_cases tc ON t.test_case_id = tc.id
LEFT JOIN test_results tr ON t.id = tr.task_id
GROUP BY t.id;
```

### 6.2 节点性能视图
```sql
CREATE VIEW node_performance_summary AS
SELECT 
    n.id AS node_id,
    n.name AS node_name,
    AVG(tr.iops_total) AS avg_iops,
    MAX(tr.iops_total) AS max_iops,
    AVG(tr.bandwidth_total) AS avg_bandwidth,
    MAX(tr.bandwidth_total) AS max_bandwidth,
    AVG(tr.latency_avg) AS avg_latency,
    COUNT(tr.id) AS test_count,
    MAX(tr.timestamp) AS last_test_time
FROM nodes n
LEFT JOIN test_results tr ON n.id = tr.node_id
GROUP BY n.id;
```

## 7. 存储过程和触发器

### 7.1 自动更新统计信息
```sql
DELIMITER //
CREATE TRIGGER update_task_summary AFTER INSERT ON test_results
FOR EACH ROW
BEGIN
    -- 更新任务统计信息
    UPDATE test_tasks 
    SET result_summary = (
        SELECT JSON_OBJECT(
            'total_results', COUNT(*),
            'avg_iops', AVG(iops_total),
            'max_iops', MAX(iops_total),
            'avg_bandwidth', AVG(bandwidth_total),
            'max_bandwidth', MAX(bandwidth_total),
            'avg_latency', AVG(latency_avg)
        )
        FROM test_results 
        WHERE task_id = NEW.task_id
    )
    WHERE id = NEW.task_id;
END//
DELIMITER ;
```

### 7.2 清理过期数据
```sql
DELIMITER //
CREATE PROCEDURE cleanup_old_data(IN days_to_keep INT)
BEGIN
    -- 删除过期的详细测试结果
    DELETE FROM test_results 
    WHERE timestamp < DATE_SUB(NOW(), INTERVAL days_to_keep DAY);
    
    -- 删除过期的节点状态历史
    DELETE FROM node_status_history 
    WHERE recorded_at < DATE_SUB(NOW(), INTERVAL days_to_keep DAY);
    
    -- 删除过期的系统监控数据
    DELETE FROM system_metrics 
    WHERE timestamp < DATE_SUB(NOW(), INTERVAL days_to_keep DAY);
END//
DELIMITER ;
```
